L04353 ### 4. ACADEMIC & SECURITY RESEARCH
L04354 **Prompt Injection Taxonomy:**
L04355 - Indirect prompt injection: attacker plants instructions in external data (webpages, emails, token metadata) that LLM treats as instructions, dominant threat per CommandSans paper.
L04356 - Tool-output poisoning: raw attribute values fed unfiltered = classic indirect injection.
L04357 - Transaction simulation as defense: inspect transaction before signing, show assets moved, permissions granted – Blockaid, Tenderly, Alchemy options.
L04358 **Critical Incidents:**
L04359 - Grok→Bankrbot: NFT privilege escalation + Morse-code injection → $174k drain, second incident 14 wallets 15 days later.
L04360 - Moltbook: 506 posts already carried hidden attacks, self-replicating prompt worms, 824 malicious skills found in ClawHub, 1.5M API tokens exposed.
L04361 - Princeton ElizaOS memory injection persists across platforms, Discord→X, fine-tuning defenses more effective than prompt detectors.
L04362 - AP2 Whispers of Wealth: functional shopping agent Gemini-2.5-Flash + ADK subverted, Vault Whisper exfiltrates user data, conclusion mandates alone insufficient.
L04363 - Anthropic Claude-for-Chrome: 23.6% attack success autonomous mode before mitigations, 11.2% after.
L04364 **Smart Account Security:**
L04365 - Session key must have no intrinsic right to modify own capability (expiry, limit, destination).
L04366 - Best practice: limited validity, scoped contracts/methods, spending limits, revocable by owner, per-tenant daily caps, per-session TTL enforced deterministically outside agent code so prompt injection can't lift.
L04367 - ZeroDev permissions compose signer + policies + action, Smart Sessions collaborative effort Rhinestone+Biconomy for flexible session management.
L04368 **Verifiable Decisions:**
L04369 - AgentAudit writes every action immutable, timestamped, verifiable, satisfies EU AI Act, who/what/when/where.
L04370 - Memstamp stamps memory/decisions/actions to blockchain for tamper-proof trail.
L04371 - Synthesis Trust Agent pattern: Parse intent → Store in FAISS → LLM safety check → Execute on Base Sepolia → Rule-based verification that transaction matched intent.
L04372 **Implication for design:** Prompt-only protections insufficient. Need defense-in-depth: enclave policy (Turnkey), on-chain validator (Smart Sessions), simulation (Blockaid), rule-based intent verifier, immutable audit, emergency revoke.

L04497 ### 7. SECURITY ARCHITECTURE (for top 3)
L04498 **Layered separation – LLM never has unrestricted fund access:**
L04499 1. **AI Planning (LLM)**: Parses user intent to structured Job spec (provider, budget, conditions). Output is JSON, not tx.
L04500 2. **Trusted Policy Enforcement (Off-chain)**: Turnkey enclave evaluates every action – address, contract, spend limit. Privy policy default deny. This layer is deterministic, outside LLM.
L04501 3. **Transaction Simulation**: Blockaid real-time protection simulates and validates before signing, transaction simulation graph shows counterparties, plus Tenderly preview.
L04502 4. **Transaction Authorization (Intent Verifier)**: Rule-based check that tx matches stored intent in FAISS – recipient, amount, chain/token.
L04503 5. **Protected Signing**: ZeroDev Kernel permission validator – signer + policies + action, Biconomy Smart Sessions with allowlist + expiry, Turnkey isolated enclave keys.
L04504 6. **Blockchain Execution**: ERC-4337 bundler (Pimlico), EIP-3009 USDC for x402, ERC-8183 escrow.
L04505 7. **Receipt Verification**: Check confirmation, reorg handling (wait N confirmations), verify event emitted.
L04506 8. **Immutable Audit**: AgentAudit writes every action immutable, timestamped, hash-chained trail you can prove wasn't altered.
L04507 **Threat modeling (max loss under compromised agent):**
L04508 - Direct injection to send funds: Blocked by enclave policy + on-chain validator. Max loss = per-tx cap, e.g., $0.50 per job, daily $250.
L04509 - Indirect injection via invoice/webpage: SentinelPrompt scans untrusted content before LLM, plus clear-signing design with simulation.
L04510 - Private key exposure: Keys never pass through server, never leave hardware boundary, unexportable enclaves.
L04511 - Recipient substitution: Intent verifier compares proposed recipient vs stored intent.
L04512 - Amount manipulation: SpendingHook enforces per-tx/daily/cumulative.
L04513 - Wrong chain/token: Chain_type enforced at wallet creation.
L04514 - Token approval exploitation: USDC allowance cap, avoid infinite approvals.
L04515 - Malicious contracts: Blockaid threat scanning identifies potentially malicious activity, MEV protection.
L04516 - Duplicate payment: Idempotency keys.
L04517 - Policy modification: Owner-only, signer cannot modify policies.
L04518 - Recovery: Instant lock overriding policies, revoke session keys immediately.
L04519 **Fails safely:** If any layer fails, transaction denied. Agent can still operate in read-only.
L04520 **Adversarial tests:**
L04521 - Paste Moltbook payload with hidden drain instruction → should be blocked by SentinelPrompt + policy.
L04522 - Gift NFT to upgrade permissions (Bankr pattern) → should fail because permissions from session validator, not NFT ownership.
L04523 - Memory injection planting fake past event → CrAIBench test, should be caught by FAISS intent history not trusting memory store as ground truth.
